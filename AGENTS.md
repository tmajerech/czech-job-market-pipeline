# Project continuity

At the start of every new conversation or task in this repository, read
`docs/project-log.md` before proposing architecture or changing code.
Read `docs/project-history.md` only when historical context is relevant.

After a material implementation change or architectural decision:

1. Update the current state and next step in `docs/project-log.md`.
2. Add a dated entry to `docs/project-history.md` explaining what changed and why.
3. Keep proposals separate from accepted decisions.
4. Verify live AWS state before describing infrastructure as deployed.

Keep the log concise enough to read at the start of each session. Link to
existing detailed documents instead of duplicating their contents.
